## 対象 opcode と仕様

### SRE / *SRE (LSR + EOR 合成命令)

メモリ値を LSR (論理右シフト: bit0 → C, bit7 = 0) し、その結果で A と EOR。
つまり `C = M & 1; tmp = M >> 1; [M] = tmp; A = A ^ tmp; N/Z フラグ更新` を 1 命令で行う。
C フラグは LSR で設定、N/Z フラグは EOR 結果で更新。

nesdev wiki: "SRE: LSR value then EOR value"

| opcode | アドレッシング | byte | cycle | nestest 初出行 |
|--------|---------------|------|-------|---------------|
| `43` | (indirect,X) | 2 | 8 | 7941 |
| `47` | zeroPage | 2 | 5 | 8012 |
| `4F` | absolute | 3 | 6 | 8083 |
| `53` | (indirect),Y | 2 | 8 | 8158 |
| `57` | zeroPage,X | 2 | 6 | 8239 |
| `5B` | absolute,Y | 3 | 7 | 8310 |
| `5F` | absolute,X | 3 | 7 | 8391 |

exec ロジック:
```
val = bus.read(op.addr)
const shifted = lsrValue(cpu, val)  // C フラグも設定される (bit0 → C, 右シフト)
bus.write(op.addr, shifted)
cpu.a = cpu.a ^ shifted
setZeroNeg(cpu, cpu.a)  // N/Z フラグを EOR 結果で更新
return 0  // RMW 系なので追加 cycle なし
```

## 実装上の注意

- SRE は `name: "*SRE"` (nestest.log 表記)
- SRE は RMW 系: read → modify (LSR) → write → EOR。cycle 数に page cross ペナルティはない
- SRE の LSR 部分は `lsrValue` ヘルパーを再利用 (bit0 → C, 右シフト)
- SRE の EOR 部分: A = A ^ shifted → N/Z フラグ更新
- 既存 SLO / RLA と同じ構造パターンで実装する (execSlo / execRla を参考)
- SRE の cycle 数は独自の base cycle (正規 LSR + 正規 EOR の合計ではない)
