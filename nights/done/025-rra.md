## 対象 opcode と仕様

### RRA / *RRA (ROR + ADC 合成命令)

メモリ値を ROR (キャリーを含む右ローテーション: bit0 → C, old C → bit7) し、
その結果で A と ADC (加算 + キャリー) する。
つまり `old_c = C; C = M & 1; tmp = (M >> 1) | (old_c << 7); [M] = tmp; A = A + tmp + C`
C フラグは ROR で一旦設定され、その C を ADC がキャリーインとして使い、ADC の結果で
C/V/N/Z フラグが最終更新される。

nesdev wiki: "RRA: ROR value then ADC value"

| opcode | アドレッシング | byte | cycle | nestest 初出行 |
|--------|---------------|------|-------|---------------|
| `63` | (indirect,X) | 2 | 8 | 8475 |
| `67` | zeroPage | 2 | 5 | 8544 |
| `6F` | absolute | 3 | 6 | 8613 |
| `73` | (indirect),Y | 2 | 8 | 8686 |
| `77` | zeroPage,X | 2 | 6 | 8765 |
| `7B` | absolute,Y | 3 | 7 | 8834 |
| `7F` | absolute,X | 3 | 7 | 8913 |

exec ロジック:
```
val = bus.read(op.addr)
const rotated = rorValue(cpu, val)  // ROR: C = old bit0, bit7 = old C
bus.write(op.addr, rotated)
addToA(cpu, rotated)  // ADC: A = A + rotated + C (ROR で設定された C を使う)
return 0  // RMW 系なので追加 cycle なし
```

## 実装上の注意

- RRA は `name: "*RRA"` (nestest.log 表記)
- RRA は RMW 系: read → modify (ROR) → write → ADC。cycle 数に page cross ペナルティはない
- RRA の ROR 部分は `rorValue` ヘルパーを再利用 (bit0 → C, old C → bit7)
- RRA の ADC 部分: `addToA(cpu, rotated)` で A に加算。C/V/N/Z フラグは ADC が最終設定
- 既存 SLO / RLA / SRE と同じ構造パターンで実装する
- RRA の cycle 数は独自の base cycle (正規 ROR + 正規 ADC の合計ではない)
- ROR が C を設定し、ADC がその C をキャリーインとして使う点が他の合成命令と異なる
