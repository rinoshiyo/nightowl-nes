## 対象 opcode と仕様

### ISB / *ISB (INC + SBC 合成命令)

メモリ値を INC (1 加算) し、その結果で A から SBC (減算)。
つまり `tmp = M + 1; [M] = tmp; SBC A, tmp` を 1 命令で行う。
C/Z/N/V フラグは SBC の結果で更新。

nesdev wiki: "ISC/ISB: INC value then SBC value"

| opcode | アドレッシング | byte | cycle | nestest 初出行 |
|--------|---------------|------|-------|---------------|
| `E3` | (indirect,X) | 2 | 8 | 6351 |
| `E7` | zeroPage | 2 | 5 | 6422 |
| `EF` | absolute | 3 | 6 | 6493 |
| `F3` | (indirect),Y | 2 | 8 | 6568 |
| `F7` | zeroPage,X | 2 | 6 | 6649 |
| `FB` | absolute,Y | 3 | 7 | 6720 |
| `FF` | absolute,X | 3 | 7 | 6801 |

exec ロジック:
```
val = bus.read(op.addr)
val = (val + 1) & 0xff
bus.write(op.addr, val)
// SBC: A - val - !C → A, C/Z/N/V フラグ更新
// 既存の addToA(cpu, val ^ 0xff) を再利用
addToA(cpu, val ^ 0xff)
return 0  // RMW 系なので追加 cycle なし (base cycle に含まれる)
```

## 実装上の注意

- ISB は `name: "*ISB"` (nestest.log 表記)
- ISB は RMW 系: read → modify (INC) → write → SBC。cycle 数に page cross ペナルティはない
- ISB の SBC 部分は正規 SBC と完全同一 (V フラグも更新する — DCP の CMP とは違う)
- 既存の `addToA` ヘルパー (`val ^ 0xff` で反転してから加算) を再利用する
- ISB の cycle 数は独自の base cycle (正規 INC + 正規 SBC の合計ではない)
